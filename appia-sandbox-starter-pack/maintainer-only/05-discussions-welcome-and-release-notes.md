## Release `v0.1.0`

**Tag:** `v0.1.0`
**Target:** `main`
**Title:** `v0.1.0: Sandbox starter version`

**Release notes:**

```
## What this release is

This is a demonstration release. It shows how a specific, agreed version of the content is captured on GitHub so it can be referred to exactly, even after `main` has moved on.

## Contents

- Sample specification (SANDBOX-SAMPLE-001, v0.1 draft)
- Onboarding material: README, glossary, FAQ, contributing guide, code of conduct
- Issue and pull request templates

## Why releases matter

- A release is a **fixed snapshot**. It does not change when new commits are made.
- It has a **permanent name** (`v0.1.0`) that can be cited in documents and emails.
- Use **Browse files** or the source code download to see the repository exactly as it was at this point.

Nothing in this release is normative.
```

## Suggested versioning (for explaining to members)

| Version | Meaning |

| `v0.x.y` | Draft, not yet formally approved |
| `v1.0.0` | First formally approved version |
| `v1.1.0` | Approved version with minor additions |
| `v1.0.1` | Approved version with editorial corrections only |

Adapt this to whatever convention Appia adopts for real specifications.
