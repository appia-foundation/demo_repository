## 2. **Add yourself to PARTICIPANTS.md**
**Labels:** `exercise`, `good first issue`

```
Practise the full change workflow: branch, edit, pull request.

1. Create a branch called `yourname/add-to-participants`.
2. Open `PARTICIPANTS.md` and add a row for yourself to the table.
3. Commit your change with a clear message.
4. Open a pull request. In the description, write `Closes #<this issue number>`.
5. Request a reviewer.

See the README for step-by-step instructions on each part.
```

## 3. **Find and fix the errors in the sample specification**
**Labels:** `exercise`, `editorial`

```
`specs/sample-specification.md` contains several deliberate mistakes: typos, inconsistencies, and gaps.

**Your task:**
1. Read through the document and note anything that looks wrong or inconsistent.
2. Comment on this issue listing what you found (include section numbers).
3. Pick **one** problem and fix it in a pull request that links to this issue.

Please keep each pull request to a single fix so it's easy to review. Check the open pull requests first so you don't duplicate someone else's fix.

There's no need to find everything. The aim is to practise.
```

## 4. **Propose a definition for "Declaration of conformity"**
**Labels:** `exercise`, `terminology`

```
Section 4.2 of the sample specification uses the term "Declaration of conformity", but it isn't defined in section 3.

**Your task:**
1. Draft a one-sentence definition in a comment on this issue and discuss it with others.
2. Once there's rough agreement, open a pull request adding the definition to the table in section 3.

Think about: where should it go in the table? Should the term be formatted consistently with the others?
```

## 5. **Review the open pull request**
**Labels:** `exercise`, `good first issue`

```
There is an open pull request waiting for a review. Reviewing is one of the most useful things you can do.

**Your task:**
1. Open the **Pull requests** tab and find the pull request titled "Fix typo in definition of assessment body".
2. Go to the **Files changed** tab.
3. Hover over a changed line and click the blue **+** to leave a comment, or use the **±** button to suggest alternative wording.
4. Click **Review changes** and choose **Comment**, **Approve**, or **Request changes**.

Leave a comment here when you've finished, and tell us how it went.
```
