# GitHub Glossary

Plain-English definitions of the terms you will see in this repository. Where it helps, there is a comparison to tools you probably already use.

| Term | What it means | Think of it as... |
|------|---------------|-------------------|
| **Repository (repo)** | A project folder that stores files and the complete history of every change to them. | A shared drive folder that remembers every version of every file. |
| **Markdown (`.md`)** | A simple text format. `#` makes a heading, `-` makes a bullet, `**bold**` makes bold text. | A lightweight alternative to Word formatting. |
| **Commit** | A saved set of changes, with a short message saying what changed and why. | "Save", plus a note to your future self. |
| **Branch** | A separate line of work, so you can make changes without touching the official version. | A copy of the document that you are drafting on. |
| **`main`** | The branch that holds the official, agreed version. | The "current approved version". |
| **Pull request (PR)** | A request to merge the changes on your branch into `main`, with space for discussion. | Sending a tracked-changes draft to colleagues for review. |
| **Review** | Feedback on a pull request: a comment, an approval, or a request for changes. | A colleague marking up your draft and signing it off. |
| **Merge** | Combining the changes from a branch into `main`. | Accepting all the tracked changes into the final document. |
| **Issue** | A tracked item for a question, problem, or proposal. | A numbered item on an action log or ticket. |
| **Label** | A coloured tag on an issue or PR, such as `proposal` or `question`. | A category tag on an email. |
| **Assignee** | The person responsible for an issue or PR. | The owner of an action. |
| **Reviewer** | A person asked to review a pull request. | Someone on the distribution list for comments. |
| **Mention (`@name`)** | Writing `@username` in a comment to notify that person. | Tagging someone in an email or chat. |
| **Fork** | Your own personal copy of a repository, used when you don't have write access to the original. | Making your own copy of someone else's folder. |
| **Clone** | Downloading a repository to your own computer. | Syncing a shared folder to your laptop. |
| **Diff** | The line-by-line view of what changed between two versions. | Compare documents in Word. |
| **Conflict** | A situation where two people changed the same lines and GitHub can't decide which to keep. | Two people editing the same sentence at once. |
| **Release / tag** | A named, fixed snapshot of the repository, such as `v0.1.0`. | A "published version 1.0" PDF. |
| **Draft pull request** | A pull request marked as not ready for review yet. | A "work in progress" draft. |
| **Suggested change** | A reviewer's proposed edit that the author can accept with one click. | A tracked-changes suggestion you can accept. |
| **CODEOWNERS** | A file that says who is automatically asked to review changes to particular files. | A standing list of required approvers. |
| **GitHub Action** | An automated task that runs when something happens, such as a check on every pull request. | A spell-checker that runs by itself. |
| **Discussion** | An open conversation thread that isn't a specific task. | A forum thread. |

Missing a term? Open an issue using the **Ask a question** template.
