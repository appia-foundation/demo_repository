# Training guide

Everything you need to learn the workflow is in this sandbox. Pick the path that matches what you will do in the real Core Specifications repository. Nothing here is normative and nothing can be broken.

## Choose your path

| If you will... | Follow this path | Time |
|---|---|---|
| Raise questions, comments or change proposals | [Contributor path](#contributor-path) | About 30 minutes |
| Review changes and take part in Working Group approval | [Reviewer path](#reviewer-path) | About 45 minutes |
| Maintain a specification as an editor | [Editor path](#editor-path) | About 90 minutes |

Everyone should start with the [README](../README.md), which covers the basic flow in your browser.

## Contributor path

1. Read the [Glossary](../GLOSSARY.md) once, so the words are familiar.
2. Raise your first issue by following [Raising an issue](raising-an-issue.md). Use the *Spec change (practice)* form and watch the labels appear.
3. Learn the basics of writing in [Markdown](markdown-cheat-sheet.md).
4. Try exercises 1 to 3 in the README, then exercises 8 and 9 in the [extra exercises](exercises.md).

You can do this path with no tools installed. Everything works in the browser.

## Reviewer path

1. Complete the Contributor path.
2. Read [Reviewing a pull request](reviewing-a-pull-request.md).
3. Try exercise 4 in the README, then exercises 10 and 11 in the [extra exercises](exercises.md).
4. Read [How Appia maps to GitHub](how-appia-maps-to-github.md) to see where your review sits in the approval process.

## Editor path

1. Complete the Contributor and Reviewer paths.
2. Read [The editor's workflow](editors-workflow.md).
3. Try exercises 5 to 7 in the README, then exercises 12 to 14 in the [extra exercises](exercises.md).
4. Read [When things go wrong](when-things-go-wrong.md) before you need it.
5. Read [Working in the Core Specifications repository](working-in-the-core-specs-repo.md) to see how the real repository differs from the sandbox.

## "I can..." checklist

Tick these off as you go. If you can do them all, you are ready for the real repository.

- [ ] Raise an issue using a form, and explain what the labels mean.
- [ ] Find an issue that needs a Working Group decision.
- [ ] Write a heading, a list, a table and a link in Markdown.
- [ ] Leave a comment on a single line of a pull request, and suggest a change.
- [ ] Approve a pull request, or request changes.
- [ ] Create a branch, edit a file and open a pull request.
- [ ] Bring the latest changes into my branch.
- [ ] Resolve a simple merge conflict.
- [ ] Look at a file's history to see who changed it and when.
