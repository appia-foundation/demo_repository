# Contributing

Thank you for taking part. This is a sandbox, so the main goal is to learn the workflow. The habits you practise here are the ones we will use on the real specifications.

## Ways to contribute

- **Raise an issue** to ask a question, report a problem, or propose a change.
- **Open a pull request** to suggest a specific change.
- **Review a pull request** raised by someone else. Reviews are one of the most valuable contributions.
- **Join a discussion** in the Discussions tab.

## Proposing a change

1. **Check for an existing issue** first, to avoid duplication.
2. **Open an issue** using the *Propose a change* template. Explain what, where, and why.
3. **Create a branch** from `main`. Suggested naming: `yourname/short-description` or `issue-12-short-description`.
4. **Make your edits** and commit them with clear messages.
5. **Open a pull request** using the template. Link the issue with `Closes #12`.
6. **Respond to review comments.** Push further commits to the same branch to update the pull request.
7. A maintainer **merges** once the required approvals are in place.

## Guidelines

- **One topic per pull request.** Small, focused changes are easier to review and quicker to approve.
- **Never edit `main` directly.**
- **Explain why**, not just what. Reviewers need the reasoning.
- **Be specific in reviews.** Point to the line, say what concerns you, and suggest an alternative where you can.
- **Keep it respectful.** See the [Code of Conduct](CODE_OF_CONDUCT.md).
- **No confidential information** in this repository.
- **Security concerns** should not be raised publicly. Follow [SECURITY.md](SECURITY.md).

## What to expect from review

- Reviewers are volunteers, so please allow a few working days for a response. `<ADJUST TO MATCH YOUR EXPECTATIONS>`
- You may be asked to make changes. That is a normal part of the process and isn't a criticism.
- If a pull request is waiting for a long time, leave a polite comment mentioning the reviewer.
